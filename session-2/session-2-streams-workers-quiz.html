Streams · Q1Memory

You must process an 8 GB NDJSON file. Which keeps memory flat?

Option A
const data = await readFile(path, "utf-8");
const rows = data.split("\n").map((line) => JSON.parse(line));
Option B
const stream = createReadStream(path);
const rl = readline.createInterface({ input: stream });
for await (const line of rl) {
  JSON.parse(line);
}

Which is better? Pick A or B.

B — streaming. A stream reads a chunk, processes it, and releases it, so memory stays flat no matter the file size. readFile loads the entire file into one string, then every parsed object — an 8 GB file blows up RAM.

Streams · Q2Completion & errors

Which prints "done" only after the file is fully written — and handles errors correctly?

Option A
createReadStream(input)
  .pipe(createGzip())
  .pipe(createWriteStream(output));
console.log("done");
Option B
await pipeline(
  createReadStream(input),
  createGzip(),
  createWriteStream(output),
);
console.log("done");

Which is better? Pick A or B.

B — pipeline. .pipe() returns immediately, doesn't wait for the destination to finish, and doesn't propagate errors cleanly. pipeline() awaits full completion and destroys the whole chain on the first error.

Streams · Q3Backpressure

Writing 100M rows to disk — which keeps memory flat?

Option A
for (let i = 0; i < 100_000_000; i++) {
  stream.write(row);
}
Option B
for (let i = 0; i < 100_000_000; i++) {
  if (!stream.write(row)) await once(stream, "drain");
}

Which is better? Pick A or B.

B — respect backpressure. write() returning false means the internal buffer is full. Waiting for drain lets the buffer empty before writing more; otherwise the write queue grows unbounded and memory climbs.

Streams · Q4CPU vs size

Which finishes faster (but produces a larger file)?

Option A
createGzip({ level: 1 })
Option B
createGzip({ level: 9 })

Which is faster? Pick A or B.

A — level 1. Lower gzip levels do less work (less CPU) but compress less, so the file is bigger. Level 9 maximizes compression at the cost of more CPU. It's a classic CPU-vs-size trade-off.

Streams · Q5Throughput

Building 100M NDJSON lines — which is faster?

Option A
const line = JSON.stringify(city) + "\n";
Option B
const line = `{"cityId":${city.cityId},"temperature":${city.temperature}}\n`;

Which is faster? Pick A or B.

B — template string. JSON.stringify pays per-object reflection and escaping overhead. A template literal writes the exact bytes directly — the session's generateHugeJson.ts even notes it's "much faster than JSON.stringify per row".

Streams · Q6Cancellation

Which actually cancels a running pipeline?

Option A
await Promise.all([
  pipeline(read, gzip, write),
  setTimeout(5000).then(() => { throw new Error("timeout"); }),
]);
Option B
const ac = new AbortController();
setTimeout(() => ac.abort(), 5000);
await pipeline(read, gzip, write, { signal: ac.signal });

Which is better? Pick A or B.

B — AbortController. A rejection inside Promise.all only rejects the Promise.all — the pipeline keeps running in the background. An AbortController signal passed to pipeline actually destroys the stream.

Streams · Q7Event loop

Your server must stay responsive while reading a 2 GB file. Which keeps the event loop free?

Option A
const data = readFileSync(path, "utf-8");
processData(data);
Option B
const stream = createReadStream(path);
for await (const chunk of stream) {
  processChunk(chunk);
}

Which is better? Pick A or B.

B — asynchronous streaming. readFileSync blocks the event loop for the entire read, so no other request is handled. createReadStream reads in chunks and yields to the event loop between them, keeping the server responsive.

Streams · Q8Decoding cost

Counting newline (0x0A) bytes in an 8 GB file — which avoids needless decoding?

Option A
const src = createReadStream(path, { encoding: "utf-8" });
for await (const chunk of src) {
  countNewlines(chunk);
}
Option B
const src = createReadStream(path);
for await (const chunk of src) {
  countNewlines(chunk);
}

Which is better? Pick A or B.

B — default Buffers. By default createReadStream emits raw Buffer chunks — count bytes directly, no decoding. Setting encoding: "utf-8" makes Node decode every chunk into a string (extra CPU + allocation) you don't need for byte-level work.

Workers · Q9Copy cost

Sending 1M city objects to a worker — which avoids the expensive copy?

Option A
const cities = citiesGen(1_000_000);
worker.postMessage(cities);
Option B
const sab = new SharedArrayBuffer(1_000_000 * 4 * 8);
const data = new Float64Array(sab);
worker.postMessage(data);

Which is better? Pick A or B.

B — SharedArrayBuffer. postMessage structured-clones by default, so 1M objects means 1M copies (CPU + memory). A SharedArrayBuffer lets both threads read the same bytes with zero copying.

Workers · Q10Share vs transfer

You're finished with the buffer on the main thread. Which is cheaper — and the receiver owns it?

Option A
worker.postMessage(sab);
Option B
worker.postMessage(sab, [sab]);

Which is better here? Pick A or B.

B — transfer. The transferList moves ownership with zero copy, but the sender can no longer use the buffer. Sharing keeps both sides able to read/write, at the cost of having to coordinate. "Transferring is not sharing."

Workers · Q11Startup cost

Handling many requests — which avoids repeated worker startup cost?

Option A
app.get("/mean", () => {
  const w = new Worker(new URL("./worker.ts", import.meta.url));
  w.postMessage(work);
});
Option B
const pool = [new Worker(...), new Worker(...)];
app.get("/mean", () => pool[next()].postMessage(work));

Which is better? Pick A or B.

B — a worker pool. new Worker() per request pays thread startup and module load every single time. A pool creates workers once and reuses them across requests — "a worker pool is not optional at scale."

Workers · Q12Event loop

Computing the mean of 5M temperatures — which keeps the event loop free so /health stays fast?

Option A
app.get("/mean", (req, res) => {
  const mean = cities.reduce((s, c) => s + c.temperature, 0) / cities.length;
  res.json({ mean });
});
Option B
app.get("/mean", (req, res) => {
  worker.postMessage([data, reqId]);
  pending.set(reqId, (r) => res.json(r));
});

Which is better? Pick A or B.

B — offload to the worker. A long reduce on the main thread blocks the event loop, so /health and every other request wait. Offloading keeps the main thread free to answer immediately.
